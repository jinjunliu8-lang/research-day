# 每日科研工作日记

使用 `research-day` CLI 完成确定性采集和发布，由你负责把证据组织成准确、可解释的科研叙事。

## 工作流程

1. 明确日期和项目；默认项目为 `topic-c`，日期为北京时间今天。
2. 如果用户没有提供实际投入时长，必须询问，禁止根据文件时间或训练时间估算工时。
3. 先运行 `research-day doctor --project <项目>`。SSH 失败时停止远程发布；只有用户明确接受基于已同步产物时才使用 `--local-only`。
4. 运行 `research-day collect --project <项目> --date <日期>`，读取生成的 `evidence.json`，核对实验、指标、图表、失败和警告。
5. 区分事实、解释、推断和计划。失败原因没有日志证据时写“需人工确认”，不得补造原因。
6. 将工时、今日目标、研究决定、补充说明和明日计划写成 annotation JSON，再用 `research-day publish ... --annotation-file <文件>` 发布。
7. 发布后检查 Markdown、科研图、附件 manifest 和 Obsidian 链接；报告日记路径、图数、证据范围和仍存在的限制。

## 科研表达规则

- 每个经验数值必须来自 `evidence.json`、指标文件或图表源 CSV。
- 当日新增的研究性量化结果应有科研图；数据不足时明确写“仅单点/样本不足”，不为凑图制作无意义图。
- 图内用英文，日记用中文图注；PNG 为 300 dpi，同时保留矢量 PDF、源 CSV 和 SHA-256。
- PCA 只能描述表征，不单独证明分类有效；严格视图不能表述为外部域泛化。
- 单随机种子结果写作 baseline，不报告稳定性结论。
- 所有失败实验进入日记；环境噪声放入折叠审计区。
- 重复发布只更新自动区，不能覆盖 `research-day:manual` 手写区。

首次配置、annotation 格式或故障处理需要细节时，阅读 [工作流与接口](references/workflow.md)。
